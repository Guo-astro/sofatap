# Compact composer and continued explicit input — October 14, 2026

This change responds to a living-room Windows report: the composer had excessive space above the keyboard, Send could disappear, and a second dictation visibly appended on the phone did not reliably reach the computer.

## Root cause and behavior

An unsupported field initially used explicit sending. A later focus revision reset its status to idle; the receiver's device-level live-edit capability then hid Send, and a new `textBegin` could import the computer's older text over the phone's unsent continuation. The regression test fails on that original transition and passes after preserving the local draft. Native editor text is also flushed before Send takes a snapshot, covering delayed keyboard delegate delivery without committing unfinished IME text.

After acknowledged text A, continuing with B sends only B. Repeated Send without new text does not duplicate A. Editing an acknowledged prefix preserves the draft and requires an explicit whole-draft resend; fallback input cannot replace computer contents. Uncertain delivery never automatically retries. A delivery receipt uses a digest and UTF-16 prefix length alongside the existing local draft, without adding a second stored copy of the delivered text.

The circular mint Send button sits inside the input panel on the right, in a separate 54-point column including its outer inset. Text and its caret stay in the editor column and cannot run underneath Send. The smaller 15-point Clear and down-arrow hide icons sit below the input box on the left, with 44-point touch targets and no backgrounds. The down arrow is distinct from the keyboard control inside the pad. The permanent capability caption, character counter and duplicate keyboard accessory toolbar are removed. Actionable connection, protected-field, loading and delivery notices remain available; pending live updates show a spinner. Only the text editor scrolls, so Send and the secondary actions cannot scroll offscreen. The strip inside the touchpad’s right edge has a separate 44-point touch target and emits bounded relative scrolling, with cancellation on inactivity, target change or multiple touches. Its indicator follows the finger, not the remote document position. An unavailable strip consumes touches without sending input, so they cannot fall through to pointer movement or clicks beneath it.

## Layout checks

Dedicated headless iPhone SE (3rd generation) and iPhone 17 Pro Max simulators used the network-disabled demo fixture, including the system keyboard. Chinese and English compact layouts kept the inset Send button and the two smaller left-aligned actions visible with the keyboard open; the larger layout also fit. The follow-up UI correction places the strip entirely inside the dot-matrix pad, below the QR control, and preserves the full composer width. The latest compact editor is 76 points tall to accommodate two lines beside the inset Send button, with a 92-point editor on larger screens. The down-arrow shortcut and background-free secondary icons were checked with the keyboard shown and hidden. Both temporary simulators were shut down and removed. Simulator.app was not opened, and other tasks' devices and physical desktop input were not used.

## Microphone feedback follow-up

The microphone button now has a 100 ms press compression/dimming and a 160 ms release, with a fixed 64-point hit target. Reduce Motion keeps the size fixed and changes brightness immediately. Only accepted explicit start/stop/cancel actions request a light haptic; stopping recording releases the audio session first, and start/cancel avoid duplicating drag-release feedback. Native unprovisioned iPhone compilation and code-path review passed. No phone was installed or microphone opened for this check; physical haptic strength/timing and animation frame rate remain unmeasured.
