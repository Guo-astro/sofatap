# Native iPad orientation — October 16, 2026

## Report and scope

[Issue #3](https://github.com/chekusu/sofatap/issues/3) reports that Sofatap stays sideways when an iPad is used in landscape. The supplied screenshot shows the portrait iPhone compatibility interface inside a landscape iPad window. The application was configured for iPhone only (`TARGETED_DEVICE_FAMILY = 1`) and declared only portrait orientation. Installing that app on an iPad did not provide a native, rotating iPad interface.

This change makes the existing app universal for iPhone and iPad. iPad supports portrait, upside-down portrait and both landscape orientations; iPhone keeps its existing portrait-only behavior. No marketing version or build number changes, receiver changes, TestFlight upload or store submission are included. The released Build 18 does not gain this fix until a new build is published.

## Implementation

- XcodeGen source and the generated Xcode project target device families `1,2`.
- `Info.plist` adds the iPad-specific orientation list without changing the iPhone list.
- The direct-compiler fallback reads the device family from the same XcodeGen source, rejects inconsistent values and supplies the required iPad icon sizes as well as its existing iPhone icons. Xcode continues to use the universal 1024-pixel app-icon asset.
- The scanner retains an `AVCaptureDevice.RotationCoordinator` and observes its preview angle. It updates only supported connection angles and releases the observation and coordinator when scanning stops. This addresses camera preview orientation when the native iPad interface rotates; QR parsing, camera permissions and capture output are unchanged.
- The existing geometry-based remote surface and scrollable sheets are retained; no pointer or receiver input is generated by layout validation.

The camera implementation follows Apple's [`videoRotationAngleForHorizonLevelPreview`](https://developer.apple.com/documentation/avfoundation/avcapturedevice/rotationcoordinator/videorotationangleforhorizonlevelpreview) documentation: preview-angle observation is delivered on the main queue and is applied directly to the preview connection. [`videoRotationAngle`](https://developer.apple.com/documentation/avfoundation/avcaptureconnection/videorotationangle) support is checked before assignment.

## Build validation

Validated with Xcode 27.0, iOS deployment target 17.0:

```sh
xcodegen generate --spec ios/project.yml
xcodebuild -project ios/SofaTap.xcodeproj -scheme SofaTap \
  -configuration Debug -destination 'generic/platform=iOS' \
  -derivedDataPath /tmp/sofatap-ipad-derived CODE_SIGNING_ALLOWED=NO build
bash ios/scripts/build-manual.sh device
```

Both build paths compile successfully. Their built `Info.plist` files were read back to verify `UIDeviceFamily = [1, 2]`, the unchanged iPhone portrait list, all four iPad orientations, and unchanged version/build values. Both packages contain iPad primary-icon metadata and icon resources. This is package/build validation, not a signed-device installation or Apple distribution validation.

## Remaining acceptance and release gates

- Real iPad rotation in both landscape directions and portrait, with usable touch controls, keyboard/composer, pairing, guide and gesture settings.
- Real camera preview and QR scanning while held in landscape and after rotation, including leaving and reopening the scanner. A simulator image does not establish physical-camera acceptance.
- Preserve iPhone portrait layout and existing input behavior.
- Before releasing the newly universal app, prepare the required **real iPad screenshots** for App Store Connect using the applicable [Apple screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/). Simulated or generated screenshots from development QA must not be used as store screenshots.

This work ends at a reviewed PR. It does not publish a new build or alter existing internal/external TestFlight availability.
